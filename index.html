About System
GVSI NetPulse

This Progressive Web Application (PWA) is designed for real-time monitoring of Gallopvision Services Inc. (A Managed Service Provider of Converge ICT Solutions, Inc.), including NAPs, LCPs, OLTs, nodes, and backbone links. Note: The data presented in this application is sourced from Gallopvision's LNOC database.

Version 3.9.20 — What's New:

  • Your App Now Goes Looking For Its Own Update (Fix): An installed app could sit on the release it was installed with for as long as you kept using it — the update only ever arrived on a fresh launch, and sometimes not even then, so the fix was to delete the app and install it again. The app asked the browser for a new version in exactly one situation: the moment it came back to the foreground. That missed the two cases that matter most — opening the app, and leaving it open all day — and the browser's own check is no help either, because it will not look more than once every twenty-four hours per installation. It now asks on every launch, on every return to the app, and every fifteen minutes while it is open, so a release you publish reaches the phone without uninstalling anything. The asking is deliberately cheap and shared: opening the app and returning to it in the same minute is still one question, not three, and the answer decides whether anything is downloaded at all.
  • A Version That Was Waiting Is Let In (Fix): A downloaded update sometimes sat waiting for its turn, and it would wait until every window of the app was closed — which an app on the home screen never does. It is now told to step in as soon as it is ready, so the version your phone has already downloaded is the one it runs.

Version 3.9.19 — What's New:

  • The OLT Tab Opens On What Is Wrong (New): The list used to be reached through a button called ALL OLTs, which was not what it showed — the rows behind it have always been the incidents only, so the label was the one thing wrong with it. It is Active Incidents now, and it is what the tab opens on. The summary above it was rearranged to match: UP, then ACTIVE INCIDENTS where TOTAL OLT used to sit, then DOWN, with the three incident types underneath. The middle card counts every OLT that is not reporting UP — the same rows the list below it draws — so the card and the list cannot disagree.
  • Impact, Not Just Status (New): Every row now carries the impact of its ticket, taken from the OLT DOWN Tickets sheet, in a new column right after the clients count. SA (service affecting) is loud, NSA is quiet, and a ticket with nothing recorded shows a dash rather than a zero — a blank is an absence, not a number. Affected Clients is scoped the same way: it says (SA) and totals the clients of the tickets marked service affecting, so it is a sharper number than the old DOWN-only total — it no longer counts an outage that affected nobody, and it does count one whose OLT is not fully down.
  • The Column Stops Repeating The Tab Name (Improvement): The last column was called STATUS and its values read OLT UPLINK DOWN, OLT SERVICE DEGRADATION, OLT UPLINK LOW POWER — each one spending its first word on the name of the tab you are already standing in. The column is INCIDENT now and the values have lost that prefix. Nothing was renamed in the data itself: the filters, the counts and the export all still match the sheet's own wording, and hovering a cell still shows it.
  • One Box Per Value (Improvement): The incident, impact and service values are drawn in a fixed-size box, so a column can no longer be as wide as its longest word and the badges line up instead of stacking as a ragged edge. The full label rides in the tooltip, so a long value wraps inside its box rather than being cut off.
  • Nothing To Export, Nothing To Click (Improvement): When the OLT list has nothing to show — no ticket matches the filter — the Export CSV and Export PDF buttons are no longer on screen. They used to sit above the card that says nothing is wrong, greyed out and unusable, taking the height the card needed.
  • The Trend Charts Are Gone (Removed): The four historical charts on the Dashboard — Incidents per Day, OLT Status Trend, Clients Affected Trend and Aging Distribution — were removed, along with the charting library they downloaded from the internet. The Dashboard now draws everything from data the app already holds, so it opens with no outside request at all and works with no connection. The daily snapshots it used to chart are still recorded exactly as before; only the charts that read them are gone.

Version 3.9.18 — What's New:

  • It Says What It Means (Improvement): The card that appears when no OLT is down now reads All OLT Systems Operational, and under it, All tracked OLTs are functional. Incident alerts will automatically render here in real time. The old wording described the panel — that it fills itself once something drops. The new wording describes the fleet you are looking at, and says where an alert will appear rather than that the card will repaint. The numbers under the sentence are still the fleet's own counts, so the card and the tiles above it cannot disagree.

Version 3.9.17 — What's New:

  • All Clear, And Nothing To Do (Improvement): The card that appears when no OLT is down used to offer a View All Healthy OLTs button — pointing at the same list the UP card and the UP filter already open, from the strip right above it. On the one screen with nothing wrong to report, the last thing it should do is hand you a chore. The button is gone, and the fleet is still one tap away.
  • A Steady Signal, Not A Tick (Improvement): The all-clear mark was a tick inside a circle, drawn inside the card's own circle — two rings fighting each other. It is now the steady signal line, the same one the login screen uses for real-time monitoring, and it pulses slowly so the card reads as being watched, and fine rather than checked once. It is the only thing moving on that screen, so it is deliberately unhurried. If your device asks for reduced motion, the ring stays still — and it never pulses on the no data arrived card, because a heartbeat over missing data would suggest something is being watched when nothing is.

Version 3.9.16 — What's New:

  • Every Module Has Its Own Face (New): The tabs were sharing shapes with screens that had nothing to do with them — NODE wore the same shield as the login page, and the access points, the cabinets and the transport links were drawn from the same three shapes. Each module now has its own: an antenna for NAP, a set of boxes for LCP, the equipment for OLT, a checked shield for NODE, a cable for BACKBONE. The glyph is bigger (22px on the phone), and it is the same one everywhere the module is named — the phone bar, the desktop tab row and the Module Snapshot cards on the Dashboard.
  • And Its Own Colour (New): Every tab used to be the same grey, so telling them apart meant reading seven small outlines one by one — and at that size they look alike. Each module now keeps its own colour — the antenna green, the boxes indigo, the equipment magenta, the shield blue, the cable amber, the charts red — on every screen it appears. The colour says which module it is and nothing more: it is not a warning and does not change when something goes down, because the numbers on the cards are what report that.
  • You Can See Where You Are (Improvement): The tab you are on used to be marked by a faint wash across the whole button, which is also what a button looks like while you are pressing it. It is now a pill behind the module's glyph, painted in that module's own colour, with the label and the underline to match — the phone bar and the desktop tab row both.

Version 3.9.15 — What's New:

  • One Icon Set, Everywhere (New): The bottom navigation, the export buttons, the header, the login screen and the empty-state cards each carried their own artwork — some filled, some outlined, in sizes that only looked right on the one screen they were written for. They are all drawn from a single modern set now, at one stroke weight, so the app reads as one thing instead of six. The login panel keeps its own hand-drawn GALLOPVISION mark, because that one is the brand and not an interface glyph.
  • The Column Sorters Speak Up (New): A sortable column header used to mark itself with two tiny text characters, and which direction you had sorted it was easy to miss. Each header now shows a proper sort icon — neutral while unsorted, a clear single arrow once you have sorted — and it takes the colour of the header it sits in, so it stays legible on the OLT, NAP, Node and Backbone tables in both themes.
  • The Icons Weigh Almost Nothing (Performance): The set they come from is around 436 KB, and an app that has to work offline hands those files to every device on every update. Only the 30 glyphs the app actually draws are shipped — about 12 KB — so the download, the install and the offline copy all stay small. A name that ever goes missing costs that one icon and never the screen around it.

Version 3.9.14 — What's New:

  • "Nothing Is Down" Now Says So (New): The OLT tab opens on DOWN, and the best news it could deliver was an empty seven-column table with a grey sentence under the headers. When no OLT is down it now shows a card that says it plainly, with the fleet's own numbers — reporting up, tracked, and zero down — and a way straight into the Healthy Fleet list. Those numbers come from the same counts the cards above it show, so the two can never disagree.
  • One Card, Four Different Facts (Fix): The other filters — Low Power, Uplink Down, Degradation — now name themselves when they match nothing, instead of all of them sharing one sentence, so "this filter is empty" no longer looks exactly like "the network is fine". And if the server returns no rows at all, the card says that rather than claiming a healthy fleet, because missing data is not good news.
  • The Age Keeps Ticking, The Exports Go Quiet (Fix): On that empty view the refresh chip used to freeze, because the screen returned before the code that updates it ever ran — so the one screen most in need of an honest timestamp was the one showing a stale one. The chip now keeps its real age there, and CSV and PDF are muted while there is nothing to write, so a download can no longer hand back a file with a single header line in it.

Version 3.9.13 — What's New:

  • Keeps Trying Before It Gives Up (Fix): When the shared request gate took over the per-module calls it also took away the retry budget each of them carried, and the default it fell back to was a single attempt. One brief hiccup on the way to the server was therefore the whole story, and a module came up with nothing in it while nothing else looked wrong. A request now makes up to three attempts with a spread-out wait between them, so two modules woken by the same edit do not re-send in lockstep.
  • A Failed Load Answers (Fix): A hiccup while the server was reading its sheet left it with nothing to send, and what came back was not an answer but a page of markup — which the app, asking for data, could only read as a wrong address. The server now names what failed and says whether asking again is worth it, so a module recovers on its own instead of reporting a broken connection.
  • No Wasted Attempts, No Wrong Data (Fix): A module name that does not exist, or a route that has since been retired, used to be answered with another module's data — the heaviest one, rebuilt from scratch. Both are now refused in a single request, before any work is done.

Version 3.9.12 — What's New:

  • Healthy OLT Fleet (New): The OLT UP card and the UP filter now open a Healthy Fleet drill-down instead of filtering the incident table. The summary is built from counts the dashboard has already loaded, so it opens instantly with no request at all; View All Healthy OLTs then loads the full UP-only list only when asked, with search, paging and a retry state if that fetch fails. The list writes its own CSV — every row the search matches, not just the 50 on screen — and holds its own export button, so it does not depend on the incident table's, which steps aside with the table. The UP pill stays lit, so the filter strip always says which of the two OLT views you are in.
  • OLT UP Payload Split (Performance): The healthy fleet travels as its own compact response with its own cache entry, separate from the incident-only payload the dashboard uses, and it is deliberately left out of the scheduled warmer — so bringing the UP rows back costs the NOC screen nothing until someone opens the list.

Version 3.9.10 — What's New:

  • Resolved Records Clear On Time (Fix): A deleted or completed row could stay on screen for up to 18 minutes while the module looked like it was refreshing, because the background warm-up wrote a long-lived snapshot and every refresh in between was answered from it without rebuilding. The snapshot now lives 3 minutes instead of 18, the warm-up rebuilds on every run instead of every other one, and the source sheet clears the affected cache within seconds of a change.
  • Honest "As Of" Stamp (Fix): The refresh chip reported when your device fetched the data, not when the server built it — so the app could honestly call itself fresh while showing a picture many minutes old. It now shows the build time, and turns amber once the payload is older than its own lifetime.
  • Changes Appear On Their Own (New): The app watches the data revision while the tab is open and re-fetches by itself when it moves, and REFRESH now genuinely bypasses the server cache it could never touch before.

Version 3.9.9 — What's New:

  • Updates Apply On The Same Visit (Fix): A published version used to wait for a second launch — the page load that triggered the update was still answered by the outgoing service worker, so the new files sat installed and unused. The app now applies them as soon as the new worker takes control, with guards so a first install does not reload and a half-typed login is never discarded.

Version 3.9.5 — What's New:

  • Covering Loading Screens (Removed): The full-cover "Gathering data…" overlay that hid each module while its data was loading is gone. The gathering state is now a small inline chip at the top of the tab, so already-rendered data stays visible during every refresh — no more covered dashboards.

Version 3.9.4 — What's New:

  • Active Users Tracking (Removed): The admin panel's Active Users card, and the heartbeat that fed it one request per signed-in client per minute, are gone. Presence was the largest single source of API requests against a metered, quota-limited deployment — and it answered a question nobody was asking on the NOC screen. The ActiveUsers sheet is left untouched; delete it in the spreadsheet if you no longer want that history.
  • Unknown Actions (Fix): An action the script does not recognise used to fall through to the data branch and answer with a full NAP payload, because type defaults to nap. It now returns a small JSON error instead — which is also what keeps a device still holding the previous shell from spending the heaviest branch in the app on a request nobody reads.
